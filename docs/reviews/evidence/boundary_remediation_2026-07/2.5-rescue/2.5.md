## D1. MEDIUM-3: session pending-heredocs from lexer events

**Where it lives:** `ParseSession.feed` step 2 (`session.py:296-307`) stops
calling `contains_heredoc`/`open_heredoc_specs` and instead consults the
result of the ALREADY-INJECTED lex seam (`SessionInputs.lex`, wired at
`scripting/command_accumulator.py:135-140` to `_lex` at :193-203, which
already passes `warn_unterminated=False` — so no spurious warning appears).

**Shape:** hoist the lex out of `_trial_parse` so `feed` lexes ONCE per
non-body line and both the heredoc decision and the parse consume that one
result:

1. body-line fast path (unchanged, O(1), no lex, no parse);
2. trailing-backslash continuation (unchanged, text-level);
3. **lex once** → seed `self._open_heredocs` from the lexer's EOF-terminated
   entries; if non-empty return INCOMPLETE/HEREDOC;
4. history-reference check (unchanged position relative to the parse);
5. parse the tokens already lexed in (3).

`heredoc_detection.py` KEEPS its role as the delimiter/terminator ALGEBRA
(`unquote_heredoc_delimiter`, `heredoc_terminator_matches`, `HeredocSpec`,
`PendingHeredocQueue`) — those are shared with the lexer and are not a second
opinion. What must stop being a live second opinion on *heredoc-ness for the
session path* is the regex scanner reached via `open_heredoc_specs`. Two
other consumers exist and are OUT of the session path but must be dispositioned
explicitly rather than ignored: `scripting/input_preprocessing.py:115` and
`interactive/line_editor_helpers.py:61,75,96`. **Proposal: leave both as-is in
2.5** (they are line-editor/continuation heuristics, not the completeness
oracle) and say so in the ledger as an explicitly-declared STILL-OPEN
boundary — closing them is a wider change than the charter. *Seeking an
explicit ruling on this scope line.*

**Declared cost delta (must be pinned, not discovered):** the heredoc-opening
line now lexes where it previously returned before lexing, so `SessionOps.
lex_calls`/`tokens_lexed` gain **+1 lex per heredoc-opening line** — a

## D2. MEDIUM-10(a): incomplete parse state vs executable type

Separate the two representations rather than validating one:

- The EXECUTABLE heredoc value gets a **non-optional body**. Concretely:
  introduce a distinct executable heredoc redirect whose body field is
  `str` (never `None`), so `Redirect(type='<<', heredoc_content=None)` is
  **unrepresentable as an executable value** — the same "make it
  unrepresentable" technique `shell_oracle.Completed` already uses in this
  tree (truncation is unrepresentable there).
- The BARE token-level parse (RD `redirections.py:153-159`, combinator
  `:117-119`) stops manufacturing executable values and produces the
  INCOMPLETE parse-state variant instead. The combinator's
  missing-operator-ID fallback in particular must stop returning a success
  ParseResult carrying an executable-shaped redirect.
- `file_redirect.py:359-361`'s late discovery becomes
  **unreachable-by-construction**; it is replaced by the type signature
  (`redirect_heredoc` takes a value whose body is `str`). I will say exactly
  what replaces it in the Phase B ledger and prove the guard BITES against a
  synthetic offender.

*Open design question I want a ruling on:* whether to add a new node class or
to keep one `Redirect` and move heredoc bodies behind a required-at-construction
invariant. I will MEASURE both in a throwaway worktree (blast radius = number
of touched call sites and test churn) before choosing, per the 2.4 standard.

## B18. R4-B + R4-E — the two improvements DECLARED, `<&` added

Both flips were RED ON BASE, measured in a discriminator-verified probe
worktree at `e36116c3` (removed after), and both now match bash on both

| shape | bash | psh BASE | psh TIP |
|-------|------|----------|---------|
| `cat <<$(x)` / `hi` / `$` | incomplete | **complete** ✗ | incomplete ✓ |
| `cat <<$(x)` / `hi` / `$(x)` | complete | **incomplete** ✗ | complete ✓ |
| `cat <<EOF "abc` / `EOF` / `def"` | incomplete | **complete** ✗ | incomplete ✓ |

1. **Substitution-bearing delimiter.** A heredoc delimiter is taken LITERALLY,
   so `cat <<$(x)` terminates on a line reading `$(x)`. The retired regex

## B33. R7-A — the regression, and why nothing of mine caught it
