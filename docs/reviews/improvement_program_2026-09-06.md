## 1. Decision

Run ONE program with ONE ledger: a **harm-ordered slot campaign whose slots are root-cause clusters**. Waves are ordered by user-visible harm (green gate → silent data loss → bash-5.3 adoption → crashes/stream corruption/security → loud conformance → measured performance → design/textbook). Inside a wave, each slot names the single `file.py#symbol` that will hold the rule, the consumers it migrates, the copies it deletes, and the guard that forbids re-duplication — so one fix closes every symptom of that mechanism and cannot silently regrow a twin. Both appraisals agree the live defects are mostly independently re-implemented rules that drifted (three "am I at word start" predicates, two `${…}` extent scanners, three IFS literals, eighteen bypassed error-prefix sites, five hand-rolled option walkers, eight `int()` leaks, three scalar→array promoters, four `WORD_LIKE` sets); the harm ordering decides *when* each cluster lands, the cluster shape decides *what* closes it.

Slots ride the merge train the previous two campaigns proved: one dev per slot in an isolated worktree cut from the current train tip, adversarial verification per integrator-plan §5, local gate + attestation + release per slot (D16: the integrator may pair two S slots with the same owner in one release; never two clusters with different owners in one diff).

Wave 0 comes first because nothing can be verified against a red gate with a drifted oracle: the 52 local failures at `6459f1a6` are the 51 triaged nodes (bash 5.3 presentation/semantic drift + 4 sandbox artifacts) plus the reviews-index test on the uncommitted r23 report, and the Linux nightly has failed on every scheduled run 2026-09-01 → 2026-09-06 (runs 33465565622 … 34008477403) — the 2026-09-06 run reports 25,514 passed / 7 failed, all seven in `tests/conformance/bash/test_printf_float_format_conformance.py` (`%a`/`%A` cells) against the unpinned ubuntu-latest system bash (`nightly.yml` runs `bash --version` with no `BASH_PATH`).

Out of scope by design (Park register §15): bash feature parity for absent features (`coproc`, `$(< file)`, `${ cmd; }` funsub, `BASH_SOURCE`), the resumable lexer/parser, the combinator's constant-factor cost, cosmetic refactors without a measured payoff.

## 4. Standing rules — deltas only

Sequence-doc rules 1–10 and integrator-plan §3 / §5 / §7 / §8 stay in force by reference. Deltas (D-numbers are cited in briefs):

- **D1 — Oracle (replaces integrator amendment A12).** The differential contract is "bash major.minor **5.3** (patch level recorded, currently 5.3.15; a patch bump is allowed and logged), resolved by `tests/harness/shell_oracle.py#resolve_bash()` (BASH_PATH → Homebrew → PATH), version recorded in `gate_attestation.json` `oracle.{path,version}` and policed by `tests/harness/oracle_policy.py`". `run_tests.py` PREFLIGHTS the oracle before any test phase: it resolves bash, prints `oracle: <path> <version>`, and refuses to start when the resolved major.minor ≠ `EXPECTED_BASH_MM = "5.3"` unless `--oracle-override` is passed (only a Wave-0-shaped re-baseline slot may pass it); `--write-attestation` records the resolved version and refuses on the same mismatch. `tests/unit/tooling/test_bash_oracle_resolution.py::test_resolved_oracle_matches_policy` is the preflight's in-suite twin for bare `pytest` runs, not the primary signal; the pytest session header and every conformance failure message print `oracle: <path> <version>`. The Linux nightly builds and runs the SAME 5.3.15. Retuning to a new bash is a Wave-0-shaped slot, never an in-slot edit.
- **D2 — Root-cause slot shape.** Every slot brief names (a) the owner `file.py#symbol` that holds the rule, (b) the consumers to migrate, (c) the copies to delete, (d) the guard and its synthetic offender. A slot may close symptoms of different harm classes when they share the owner; it is sequenced by its most severe harm and its brief names that harm class first (silent-loss / crash / conformance / perf / textbook). Verifiers reject a slot whose diff leaves a second implementation of the rule alive.
- **D3 — Actual-target pins (C244).** A pin asserts the actual effect: the cwd via `pwd -P`/`os.getcwd()` and a file placed (cd), the executable actually dispatched (PATH), the bytes actually written to the fd (redirects), the input actually consumed / fd position (mapfile, read), the behavior of the re-parsed serialization (`declare -f` → `eval`, `--format`), the exit status of the NEXT command. Return code, restored string or AST equality alone does not close a Wave 1 row.
- **D4 — Unsandboxed gate; honest skips.** The gate runs outside any filesystem/process sandbox (seatbelt denies `ps`, AF_UNIX bind, `/dev/stdout` by path); the four ENV tests gain `pytest.skip` on a probed precondition so a sandboxed run reports SKIP, never FAIL.
- **D5 — Version and platform classifiers.** A psh change that follows a bash 5.3 change cites the `CHANGES`/`NEWS` item (`/opt/homebrew/Cellar/bash/5.3.15/share/doc/bash/CHANGES`) in the test docstring, or says "empirical, 5.3.15". Version-sensitive rows carry `min_bash: "5.3"` (golden) or `@pytest.mark.oracle_min("5.3")` (pytest) — applied to exactly the Wave 0 retuned rows — so an older oracle SKIPS them with a count. The `oracle_min` marker is registered in `pytest.ini` `markers` (`xfail_strict` is on), and the 0.1 ratchet against bash-version literals whitelists exactly these two forms. Platform-sensitive rows use a probed predicate on the oracle host (`oracle_feature('x87_long_double')`), never a version or OS literal in test code.
- **D6 — Mode-varied pins; combinator via its own API.** Every behavioral pin runs in `-c`, script-file and stdin modes (failure shape differs by mode — C007/C040). Interactive facts get a realistic-terminal PTY leg with independent probe construction. Combinator facts are verified through the direct combinator API, not `--parser combinator -c` alone (C178: the RD trial parse hides over-acceptance).
- **D7 — Harm-first verification; second bounce may split.** Integrator-plan §5 (fresh adversarial rounds, novel rows, replay every red claim, re-verify to zero, guard offenders, final-SHA differentials) is the floor. The verifier attacks the slot's named harm class first (a Wave 1 verifier constructs a "did the data go to the wrong place" row the dev's suite lacks). After a SECOND bounce the integrator may SPLIT the slot into smaller briefs instead of running a third round on the same brief.
- **D8 — Pre-handoff smoke (closes C245).** Before handoff the dev runs `python run_tests.py --quick`, the touched test modules, `ruff check psh tests tools`, and `mypy`, and pastes the four tails into the handoff. The full gate stays the integrator's ceremony step; per-PR CI stays disabled by user decision — no new CI is added.
- **D9 — Same-day registration.** Defects discovered during a slot are registered in `LEDGER.md` as `N-rows` (`W0-N1`…) with an owning slot on the day they are found; they never ride an unrelated slot's diff.
- **D10 — Ownership by cid.** Every ledger row, brief, pin docstring, golden `description`, and CHANGELOG line names the cid(s) it closes; `grep -rn "C[0-9]\{3\}\b" tests/` must find every closed row's pin.
- **D11 — Nightly is a wave-close criterion.** No wave closes until the first scheduled nightly after its last merge is green on the pinned 5.3.15 (or its residual is a written Linux-watch ledger row with an owner).
- **D12 — Provenance stamps (C241).** "Verified against bash 5.2" in an existing docstring is provenance; it is rewritten only when a slot touches that file — no tree-wide rewrite. `tests/unit/tooling/test_oracle_version_comments.py` forbids NEW "bash 5.2" claims (ratchet with a frozen baseline count that only decreases).
- **D13 — Comments state the invariant and the reproducing command.** ≤ 1 campaign ID per file; no pointers into gitignored `tmp/`; any irreplaceable sketch is drift-locked in `tests/unit/tooling/test_doc_snippets.py` (C087/C133/C188/C224).
- **D14 — `HOME` via `env=`.** Never reassign `HOME` in-script before expanding `~` in a conformance row — the Homebrew 5.3.15 bottle links installed readline and resolves `~` from the startup environment (oracle-binary artifact, not psh semantics). Probed on the 5.3.15 bottle: even `export HOME=/probe-home; echo ~` still prints the login home, so in-script `export` does not help; tilde-pattern pins (1.11) pass `HOME` via `env=`, while `cd`/empty-`HOME` pins (1.4) read `$HOME` directly and may assign in-script.
- **D15 — Probe invocation.** `env -u PWD -u OLDPWD` from a fresh `mktemp -d` (psh trusts an inherited stale `$PWD`); `python -m psh -c` prepends CWD to `sys.path`, so A/B harnesses set cwd to the tree under test and check `psh.__file__`. Direct `subprocess` in oracle-bearing modules stays banned by `test_no_direct_spawn_in_oracle_modules.py`. compare-bash is invoked only as `python -m pytest tests/behavioral --compare-bash -n auto -q` (A6).
- **D16 — Release pairing.** Integrator-plan §7 is per slot; the one delta is that two S slots with the SAME owner file may share one release (one version bump, one attestation), never two clusters with different owners. Wave 0 is the other exception: its three slots are commit boundaries on one branch and ship as ONE release (§6).
